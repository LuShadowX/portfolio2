04 · New features in detail

Repo index

A live list of every repository on my GitHub account, sitting between the projects and the contact section. It's the main client-side application in the project and covers most of Units IV, V and VI.

Search with filters

The search box reads GitHub-style filters using regular expressions: lang:python, topic:cli, stars:>2, stars:1..5, is:fork, plus normal words. If a filter can't be read, it says so instead of failing silently.

Pin shelf (Drag and Drop + localStorage)

Visitors can keep up to six repositories on a shelf. They can drag a card onto it, press its Pin button, or use the keyboard: arrow keys move a focused pin and Delete removes it. The order is saved in localStorage, so it's still there after a reload.

04 · New features in detail

Contact form

The old form only had the browser's built-in checks. The new one validates every field with JavaScript and regular expressions, explains errors in plain words, and never loses what the visitor typed.

From the desk

  • Two live clocks using Intl.DateTimeFormat with time zones: mine (Asia/Kolkata) and the visitor's. They tick exactly on each second.
  • Time-zone gap: the offset name like "GMT+5:30" is read with a regex and turned into minutes. The note changes with my local hour.
  • Map: OpenStreetMap inside an <iframe> with title and loading="lazy".
  • "How far away are you?" asks for location only on click (Geolocation API), handles every error code, and computes the distance with the haversine formula. Nothing is stored.
  • Voice note: a custom <audio> player with play/pause and a seek bar, driven by media events. It stays hidden until a recording file exists.

1. Fetching with a timeout and a fallback

repo-index.js · lines 65–79async function fetchJSON(url, timeout = 8000) {
    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), timeout);
    try {
        const res = await fetch(url, { signal: controller.signal });
        if (!res.ok) {
            const err = new Error(`${res.status} ${res.statusText} for ${url}`);
            err.rateLimited = res.status === 403 && res.headers.get('x-ratelimit-remaining') === '0';
            throw err;
        }
        return await res.json();
    } finally {
        clearTimeout(timer);
    }
}

fetchJSON wraps fetch. An AbortController cancels the request after 8 seconds. A non-OK response becomes an Error carrying a rateLimited flag, read from GitHub's rate-limit header.

finally clears the timer whether the request worked or not.

repo-index.js · lines 82–100async function loadRepos({ fresh = false } = {}) {
    const cached = fresh ? null : repoCache.read();
    if (cached) return { repos: cached, source: 'cache' };

    try {
        const live = (await fetchJSON(API)).map(trim);
        repoCache.write(live);
        return { repos: live, source: 'live' };
    } catch (err) {
        debug.warn('GitHub API unavailable, falling back to the snapshot.', err);
        const snapshot = await fetchJSON(SNAPSHOT);
        return {
            repos: snapshot.repos,
            source: 'snapshot',
            savedAt: new Date(snapshot.savedAt),
            reason: err.rateLimited ? 'rate-limit' : err.name === 'AbortError' ? 'timeout' : 'offline'

}

Three steps: the session cache first, then the live API, then the copy committed with the site. The result says which one was used, so the page can tell the visitor honestly (Fig 29).

2. Parsing search filters with regular expressions

repo-index.js · lines 104–107// Plain words plus a few GitHub-style qualifiers:
//   lang:python  topic:ml  stars:>2  stars:1..5  is:fork  is:source
const QUALIFIER = /\b(lang|language|topic|stars|is):("[^"]*"|\S+)/gi;
const NUMBER_RULE = /^(?:(>=|<=|>|<)?(\d+)|(\d+)\.\.(\d+))$/;

QUALIFIER finds every key:value pair. Group 1 is the key, and group 2 is the value (a quoted phrase or a single word). The g and i flags match all of them, in any case.

NUMBER_RULE accepts 5, >2, <=10 or a range 1..5.

repo-index.js · lines 124–159export function parseQuery(input) {
    const tests = [];
    const problems = [];
    let forkMode = null;

    const rest = input.replace(QUALIFIER, (token, key, raw) => {
        const value = raw.replace(/"/g, '').toLowerCase();
        switch (key.toLowerCase()) {
            case 'lang':
            case 'language':
                tests.push(repo => (repo.language ?? 'other').toLowerCase() === value);
                break;
            case 'topic':
                tests.push(repo => repo.topics.some(topic => topic.includes(value)));
                break;
            case 'stars': {
                const rule = starsRule(value);
                if (rule) tests.push(repo => rule(repo.stars));
                else problems.push(token);
                break;
            }
            case 'is':
                if (value === 'fork') forkMode = 'fork';
                else if (value === 'source') forkMode = 'source';
                else problems.push(token);
                break;
        }
        return ' ';
    });

    rest.toLowerCase().split(/\s+/).filter(Boolean).forEach(word => {
        tests.push(repo => `${repo.name} ${repo.description} ${repo.topics.join(' ')}`.toLowerCase().includes(word));
    });

    return { tests, problems, forkMode };
}

replace with a callback visits every filter. A switch turns each one into a test function, and anything it can't read goes into problems (Fig 12). Whatever text is left becomes plain-word searches.

3. Higher-order functions: filter, sort and reduce

repo-index.js · lines 208–217function visibleRepos() {
    const { tests, problems, forkMode } = parseQuery(state.query);
    const compare = SORTS[state.sort];
    const list = state.repos
        .filter(repo => forkMode === 'fork' ? repo.fork : forkMode === 'source' ? !repo.fork : state.forks || !repo.fork)
        .filter(repo => state.language === 'all' || (repo.language ?? 'Other') === state.language)
        .filter(repo => tests.every(test => test(repo)))
        .sort((a, b) => state.reverse ? compare(b, a) : compare(a, b));
    return { list, problems };
}

Every visible list is computed from state. Three filter calls handle the forks switch, the language menu and the search tests. sort uses a comparator from the SORTS lookup object, reversed when a table header is clicked twice.

            }

            } catch {

            }
        },
        remove(key) {

        }
    };
};

Storage can throw (private browsing, blocked cookies), so every call is wrapped and fails soft. wrap is a factory: each object it returns remembers its storage name in a closure. Values go through JSON.stringify/parse.

desk.js · lines 11–18const OFFSET_RE = /GMT(?:([+-])(\d{1,2})(?::(\d{2}))?)?/;
function offsetMinutes(timeZone, date = new Date()) {
    const name = new Intl.DateTimeFormat('en-US', { timeZone, timeZoneName: 'shortOffset' })
        .formatToParts(date)
        .find(part => part.type === 'timeZoneName')?.value ?? 'GMT';
    const [, sign = '+', hours = 0, minutes = 0] = name.match(OFFSET_RE) ?? [];
    return (sign === '-' ? -1 : 1) * (Number(hours) * 60 + Number(minutes));
}

Intl formats the time-zone name as "GMT+5:30". The regex pulls out the sign, hours and minutes, and the function returns minutes east of UTC. The difference between two zones gives "I'm 4.5 hours ahead of you".

desk.js · lines 35–42// Great-circle distance in km (haversine)
function distanceKm(a, b) {
    const rad = (deg) => (deg * Math.PI) / 180;
    const dLat = rad(b.lat - a.lat);
    const dLon = rad(b.lon - a.lon);
    const h = Math.sin(dLat / 2) ** 2 + Math.cos(rad(a.lat)) * Math.cos(rad(b.lat)) * Math.sin(dLon / 2) ** 2;
    return 2 * 6371 * Math.asin(Math.sqrt(h));
}

11 · Conclusion

What I learned

Portfolio2 puts every part of CSE326 into one site that people actually use, rather than ten separate lab pages.

  • HTML is the foundation for accessibility and SEO. Choosing table, fieldset, time and proper labels made the page work for screen readers and search engines with almost no extra code.
  • Modern CSS can do layout jobs that once needed JavaScript. The container query restacks the table based on the space it actually has, not just the screen width.
  • Real data is messy. APIs hit rate limits, users go offline, and storage can be blocked. Planning for failure (cache → API → snapshot, safe storage, guard) is what makes an app feel reliable.
  • Small, well-named modules are easier to debug. When something broke, the ?debug output pointed to the exact module.
  • Browser APIs are powerful but need consent and care. Location is requested only on click, never stored, and every error case has a friendly message.

Possible next steps

  • A light/dark theme switch saved in localStorage
  • A service worker so the whole site works offline
  • Recording and adding the voice note
